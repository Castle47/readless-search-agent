# SQLite RAG v3：BM25 与向量检索融合

本文同步自 ReadLess 宿主开发记录；独立仓库验证见 [更新记录](UPDATE-2026-11-12.md)。

2026-11-12。接续 [SQLite 结构 v2](sqlite-rag-schema-v2.md)，当前实现为 Schema 3，排序方法标识 `bm25-vector-rrf-v1`。

后续切分规则已升级为 [boundary-v2-spacy](rag-chunking-v2.md)：英文使用 spaCy Sentencizer 和 300 词／30 词重叠，中文保留字符预算。数据库结构和本页排序公式不变，但刷新旧索引时会重新切分，文本变化的片段需要重新生成向量。

## 查询流程

1. 使用同一套本机分词规则处理文档和查询。中文使用固定版本 jieba 0.42.1 的搜索模式，关闭 HMM；英文及数字规范化为小写，全角字符进行 NFKC 规范化。只对查询移除有限的提问套话与停用词，最多使用 64 个不同检索词。不是繁简转换、词干归一化或语义同义词扩展。
2. 每个资料库分别执行 FTS5 BM25 检索及已有的向量精确扫描。FTS 查询词经过分词和引号转义式构造，不执行用户提供的 MATCH 表达式。FTS5 的 BM25 分数越小越好。
3. BM25 的路径、标题、正文权重依次为 0.25、3、1。向量分支使用余弦相似度，不再把 BM25 原始分数与余弦分数直接相加。
4. 在各分支截取候选之前检查文件内容哈希、有效状态和来源权限。网站和原创博客先生成可用路径集合，检索后再次检查当前可见性/版本；文件夹禁用后仍按原流程排除。
5. 向量候选要求余弦相似度至少 0.3；关键词候选要求覆盖至少一半的有效查询词。每路最多保留 50 个候选。单个资料库先融合，研究流程从各库收集最多 50 个融合候选，再合并。
6. 使用 RRF：`score = Σ 1 / (60 + rank)`，缺席某一路就不计该路贡献。全局合并后重新计算向量名次；不同资料库的 BM25 原始分数不直接比较，保留各自库内关键词排名。最多选择 8 个片段，再按资料库、文件和修订合并来源。

这是分库检索的融合方案，不是全站统一词频统计下的全局 BM25。一个小资料库的第一名与大资料库的第一名可能具有不同的相关程度，因此保留独立相关性门槛与可审计评分。当前候选数、覆盖率和余弦门槛是初始默认值，不声称经过真实用户查询集调优。

## 先行初稿

RRF 分数只反映排名，不能当成置信度。新结果必须同时满足以下条件才标记 `strong_match`：

- 全局向量名次前 5，库内 BM25 名次前 5；
- 余弦相似度至少 0.8；
- 有效查询词覆盖率至少 0.5。

先行初稿只接收被标记的强相关来源。正式研究仍可使用仅命中一个检索分支的材料。旧运行回放没有新方法标识时，保留历史的 0.8 分数解释；新运行不使用旧的混合分数门槛或“最高分减 0.2”筛选。

存储的来源结果包含 retrieval_method、strong_match、retrieval_score，以及每个片段的原始 BM25 分数、库内 BM25 名次、余弦相似度、向量名次、关键词覆盖率和 RRF 分数，供排查使用。这些字段不把材料变成已验证事实。

## 表结构变化

仍为 files、chunks、embedding_cache、metadata 四张普通表与 chunks_fts 一张 FTS5 虚表。

| 字段/表 | v3 变化 |
| --- | --- |
| chunks.search_text | 改为仅保存正文的分词结果 |
| chunks.search_path | 新增：路径的分词结果 |
| chunks.search_title | 新增：标题的分词结果 |
| chunks_fts | 对上述三个字段分别建全文索引，支持不同字段权重 |
| metadata.tokenizer_version | 新增：`jieba-0.42.1-search-hmm-off-v1` |
| PRAGMA user_version / metadata.schema_version | 升为 3 |

片段原文、字符位置、页码、文件哈希、片段 ID 和已有向量保持。更新标题时只更新全文索引，不重新计算向量。全文索引的插入、修改、删除和 VACUUM 稳定行 ID 规则继续有效。

## 迁移与部署

- v2 库第一次由新代码打开时，先保存 `<库名>.v2-backup.sqlite`；在事务中新增字段、重新分词并重建 FTS5，失败整体回滚。
- v1 库继续支持直接迁移，保留 `.v1-backup.sqlite`。迁移不调用 embedding 或生成模型。
- 新增固定依赖 jieba 0.42.1，已更新 pyproject.toml 和 uv.lock；需按锁文件安装或重建研究容器。仅把 Python 源码复制到没有新依赖的旧镜像不够。
- 原文和向量没有变化时，不要求用户重新生成整个资料库向量。
- 向量检索仍为精确扫描，没有引入 ANN 或独立重排模型。分词和阈值的真实效果仍需实际查询集评估，离线回归不等同于线上效果证明。

## 验证

新增离线回归使用真实 SQLite FTS5 与受控向量，检查稀有词权重、标题权重、长度归一化、中文复合词、两路独立召回、RRF 一致性、分库合并、来源撤回/过期不占名额、标题更新不重算向量、v2 迁移和失败回滚，以及先行初稿只使用强相关来源。没有通过手填答案生成模型回答。

执行结果：后端单元测试 185 项通过，包含 13 项新增 BM25/RRF 回归；`npm test` 414 项通过、2 项跳过、0 失败；`npm run verify` 通过。新增分词/融合模块、存储和检索模块、博客适配及新增测试的 Ruff 检查通过。

本机 Docker 状态检查在 12 秒内没有响应。本次完成源码、锁文件和离线验证，没有启动生成模型任务，也未确认容器加载新版本或容器中的真实索引完成迁移。Docker 恢复后使用既有 `docker compose up -d --build` 重建服务，新代码首次访问各库时执行上述迁移。无需为迁移重新计算向量；真实检索质量与完整研究回答仍待运行环境恢复后验收。
