# RAG 切分 v2：spaCy Sentencizer 与英文 300/30

本文同步自 ReadLess 宿主开发记录；独立仓库验证见 [更新记录](UPDATE-2026-11-12.md)。

2026-11-12。当前规则标识为 `boundary-v2-spacy`，替代 [boundary-v1](rag-chunking-v1.md)。数据库仍为 SQLite Schema 3；本次修改切分逻辑、依赖和索引规则版本，不修改 BM25/RRF 排序或原始资料。

## 英文分句

使用 `spacy.blank("en")` 创建英文分词器，仅添加 `sentencizer`。没有下载或加载 `en_core_web_sm` 等训练模型，没有句法分析器，也不调用大模型 API。

spaCy 的英文 tokenizer 先识别缩写、小数等，再由 Sentencizer 标记句子边界。已实测 `Dr. Smith`、`e.g.`、`i.e.`、`3.14`、`J. R. Smith` 和 `U.S. office` 不会因为这些内部句点被错误拆句。这仍是规则分句，不能保证解决所有缩写歧义或复杂语言现象。

依赖约束为 spaCy 3.8 系列，锁文件本次解析为 3.8.18。索引规则记录实际安装的 spaCy 版本和空白英文管线标识；依赖版本变化会改变索引签名。仅复制源码到未安装 spaCy 的旧容器不够，需按锁文件重建环境。

## 长度和重叠

| 文本 | 默认预算 | 重叠 |
| --- | --- | --- |
| 不含汉字、含英文字母的文本 | 最多 300 词 | 最多 30 词，优先对齐句子/段落 |
| 中文、含汉字的中英混合文本 | 最多 1800 字符 | 最多 200 字符，沿用已有规则 |
| 其他无法按上述规则识别为英文的文本 | 最多 1800 字符 | 最多 200 字符 |

这是保守的字符规则路由，不是语言识别模型。判断单位是当前提取的文本段（PDF 通常为一页；内嵌图片编码排除后，两侧文本分别处理）。包含汉字的整段继续采用字符预算，不声称中英混合文本中的英文段落已单独路由。

“词”定义为 spaCy 分词结果中至少含一个字母或数字的 token，排除纯标点和空白；它不等于生成模型的 token。例如缩写和小数一般是一个词，缩略形式可能拆成多个 spaCy token。切分边界仍避免落在 `can't` 等表面单词内部。

英文优先在接近预算的段落边界结束，其次保留完整句子。若下一句会超过 300 词，允许当前片段提前结束；单句超过预算时，按换行、空白词边界或标点继续拆分。普通英文片段不再受到 1800 字符上限限制。

重叠不是固定复制任意 30 个词：在不超过 30 词的范围内，优先保留完整句子。结构保护或无法对齐时可以缩短或取消重叠；无完整句子可保留时，可从词边界保留句尾。常规每句 10 词的测试能够得到 300 词片段和正好 30 词重叠。

为避免单个超长标识符、网址或大量符号形成无界片段，英文另有 6000 字符硬上限，优先寻找自然边界，必要时硬切并计入诊断。它是极端输入保护，不是精确的向量模型 token 限制。

内部调用显式传入旧 `size`/`overlap` 参数时，保留字符预算兼容接口；英文句子边界仍由 spaCy 提供。正常索引入口不传这两个参数，因此自动采用上述 300/30 或 1800/200 规则。

## 代码、表格与来源位置

继续识别 Markdown 围栏代码块和管道表格。英文结构整体不超过 300 词和 6000 字符时尽量完整保留，即使已经超过 1800 字符；中文结构按原字符预算判断。

超预算结构优先按完整代码行/表格行拆分，极端长行才硬切；重叠不会从可完整保留的结构内部开始。为维持精确引用，仍不人为补围栏或复制表头。

片段始终是原文连续切片。字符偏移、行号、PDF 页码、Base64 图片排除与原文哈希检查保留。没有改变原文、翻译、图片或历史研究证据。

## 大文本处理

spaCy 每次处理最多 65536 字符，优先在段落或空白处划分处理窗口，不把窗口末尾自动当作句末。窗口边界附近可能少识别一个真正句末，但不人为加入一个假的句末。切分后的引用位置仍使用整个原文段的坐标。

缓存一套空白管线，使用 spaCy 的 memory zone 限定临时词汇生命周期，不保留 Doc/Token 对象。分析后只留下词和句子的整数位置，避免持续索引不同文档时无限积累词汇对象。

## 索引规则与状态

`files.index_signature` 包含新切分版本、spaCy 实际版本、英文 300/30、中文 1800/200 和英文字符保护上限。完整刷新后 `metadata.text_index_version` 更新为 4，数据库 `schema_version` 仍为 3。

旧文件即使内容没变，下次刷新也会因为签名不同而重新切分。片段实际模型输入不变时复用向量；边界变化的片段重新计算。新片段、来源位置及全文索引仍以文件为单位事务替换，失败不暴露未完成的新版本。

在原有切分诊断上增加：

| 字段 | 含义 |
| --- | --- |
| sentencizer_version | spaCy 版本和规则管线标识 |
| english_word_limit / english_overlap | 英文词数预算与重叠预算 |
| english_max_chars | 英文极端输入字符上限 |
| english_word_chunks | 本次按英文词数预算尝试切出的片段数 |
| character_chunks | 本次按字符预算尝试切出的片段数 |
| sentencizer_windows | 本次实际执行英文分句的处理窗口数 |

这些是本次尝试的统计；跳过未变化文件时为零，不等同于数据库已有片段总数。

## 验证

新增 19 项专项回归覆盖无训练模型管线、常见缩写、小数、姓名首字母、300 词与 30 词重叠、完整句优先、缩略形式不被截断、结构保护、超长单词、分句窗口、中文及混合文本、图片编码排除和索引规则升级。

执行结果：全套后端单元测试 229 项通过；最新切分专项 44 项通过（其中英文新增 19 项，包含于单元测试）；`npm test` 416 项通过、2 项跳过、0 失败；`npm run verify` 和本次 Python 文件的 Ruff 检查通过。

本机 Docker 状态检查在 12 秒内没有响应。本次没有确认容器加载新依赖/代码，也没有对容器内的真实资料库重新切分或运行生成模型回答。Docker 恢复后，通过既有 `docker compose up -d --build` 按锁文件重建服务，再刷新各资料库索引。不能把离线测试计为真实模型回答验收。
