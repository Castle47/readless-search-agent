2026-11-12。本次仅优化检索片段，不修改原文、网页阅读器、BM25/RRF 排序或生成模型。实现：`services/rag_chunking.py`，共用于原有笔记、指定文件夹、博客和网站资料的索引。

## 切分规则

- 每个片段最多 1800 个 Python Unicode 字符，重叠最多 200 字符。字符数不是字节数，也不是模型 token 数。
- 普通文本优先在后半段找到段落边界，其次尝试句末标点、换行、空白词边界、逗号/冒号等标点；找不到时尝试较早边界，最后才按字符上限硬切。
- 段落边界包含空行、Markdown 标题开始位置，以及识别出的代码块/表格起止位置。句末识别为规则匹配，不是语言模型或完整语言学分句器。
- 支持 Markdown 反引号/波浪线围栏代码块，以及带分隔行的管道表格（含单列表格）。结构整体不超过 1800 字符时，片段起止边界不会落在其内部；剩余空间不足时，结构移入下一片段。
- 超过 1800 字符的代码块和表格优先按完整代码行/表格行拆分。若某一行本身超过上限，仍须硬切；不假称所有结构都能完整保留。
- 重叠起点也对齐自然边界，实际重叠为 0–200 字符。不会为凑够 200 字符而截断能完整保存的代码块或表格；重叠妨碍下一完整结构容纳时，放弃该次重叠。
- 不生成仅重复前一片段、没有新增原文的片段。纯空白不单独生成片段。

## 来源保真

始终返回 `(原文起始位置, 原文连续切片)`，满足 `片段正文 == 原文[start:end]`。保留字符范围、原文行号和 PDF 页码。

内嵌 `data:image/...;base64,...` 继续排除，各侧文本保留原文绝对字符坐标，不把移除图片后的文本重新编号。

Python `str` 按 Unicode 码点切片，不会从 UTF-8 多字节编码中间截断。极端硬切仍可能拆开组合字符或 ZWJ 表情的字素簇；本次没有实现完整 Unicode 字素簇分割。

为保证精确引用，超长代码不人为添加围栏，超长表格不复制表头到片段正文；这类结构的片段可能只包含续行。HTML 表格、复杂嵌套 Markdown、缩进代码块和 PDF 的视觉表格不保证被识别为独立结构；PDF 继续按页提取后切分。

## 索引更新与报告

数据库表结构仍是 Schema 3，不新增表。`files.index_signature` 加入 `boundary-v1`，完整刷新后的 `metadata.text_index_version` 更新为 3。

即使文件内容没有改变，只要索引规则标识不同，下次刷新仍会重新切分。原先按固定字符切分的旧库迁移时保留旧规则标识，不把旧片段误标为新规则产物。仅升级 SQLite 表结构不会自动重算所有片段；要通过既有刷新索引入口应用新规则。

仍以“文件路径＋实际片段文本＋模型/输入版本”复用已有向量。边界变化导致文本变化的片段需要重新计算向量；完全相同的输入继续复用。新片段全部准备好并复核源文件哈希后，在事务中替换该文件的片段和全文索引。旧研究的冻结证据不受影响。

索引进度与报告新增 `chunking` 信息：

| 字段 | 含义 |
| --- | --- |
| version | 当前切分规则版本 boundary-v1 |
| chunks | 本次实际尝试切出的非空片段数，不含跳过的未变文件；不等同于最终有效片段总数 |
| hard_splits | 找不到可用边界而在长度上限硬切的次数 |
| oversized_code_blocks | 本次处理的超长代码块数量 |
| oversized_tables | 本次处理的超长管道表格数量 |
| excluded_image_payloads | 本次排除的内嵌图片编码数量 |

失败文件的已尝试切分也会计入诊断，不能据此宣称已成功入库；实际有效片段总数仍使用报告顶层 `chunks`。

## 验证

新增测试覆盖段落、句子、英文词边界、标题、两类围栏、单列/多列表格、超长结构、极端长行、中文/Emoji/组合字符、CRLF、未闭合围栏、Base64 排除、边界参数及 80 组固定种子的随机组合。检查长度上限、原文坐标、非空白文本无遗漏、没有仅含重复原文的片段，以及索引规则升级后的重新切分、向量复用、全文索引一致性。

执行结果：25 项切分专项测试通过；后端完整单元测试 210 项通过；`npm test` 416 项通过、2 项跳过、0 失败；`npm run verify` 与本次修改文件的 Ruff 检查通过。

本机 Docker 状态检查在 12 秒内没有响应，因此没有确认研究容器加载本次代码或既有真实索引完成重新切分，也没有执行生成模型回答复测。Docker 恢复后，通过既有 `docker compose up -d --build` 加载新代码，再使用既有资料刷新入口；原有 Obsidian 库使用既有 index-vault 命令。不能把受控向量测试当作真实模型回答验收。
